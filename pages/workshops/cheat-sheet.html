Cowork Quick Reference

Everything you need to remember on one page — model defaults, permission modes, the five prompt principles, the /schedule constraint, session hygiene, and the three governance rules: the folder rule, the verification habit, and where work goes when it needs a central audit trail.

Print-friendly · keep it handy
01 — Models

Model & effort defaults

Pick the right model for the job — Opus is powerful but costs more of your usage allowance. Start with Sonnet.

01
Sonnet — everyday default
Documents, drafts, summaries, analysis. This is your workhorse. Use it for anything that doesn't require edge-case judgment.
02
Opus — hardest calls only
Complex reasoning, edge-case legal or underwriting decisions. Reserve it — Opus consumes significantly more of your usage allowance.
03
Effort levels
high is the product default. Step down to medium for routine work to save usage allowance. Use low for quick lookups only.
02 — Permission modes

Permission modes

Permission mode controls whether Cowork pauses to ask before taking action. When in doubt, ask first.

01
Ask before acting
Pauses for approval before any file write, delete, or shell command. Use for untrusted content — emails, web pages, uploaded files from outside Gen Re.
02
Act without asking
Runs without pausing. Use only for trusted, known files while actively supervising. Riskier — a hidden instruction in a file can redirect the agent.
03
Default rule
Start every new task with "Ask before acting" until you know the files are clean. Switching to act-without-asking is a deliberate choice, not the default.
03 — Prompting

The five prompt principles

These five moves close the gap between what Cowork produces and what you actually needed.

01
Outcome over steps
Say what you want, not how to do it. Let Cowork choose the method — that's what it's for.
02
Define done
State what good output looks like and what should never appear. "A two-page summary, no raw numbers without context, no customer PII in the subject line."
03
Flag gaps, don't fill them
"If something's missing from the file, say so — don't estimate." Prevents confident-sounding fabrication.
04
Name the reader
"Write this for an underwriting committee unfamiliar with the cedent." Context about the audience shapes tone, length, and what gets explained.
05
Iterate with one sentence
Redirect with a single sentence rather than restarting. "Make the executive summary one paragraph and move the detail to an appendix."
04 — Scheduling

/schedule & its constraints

Recurring tasks are powerful — but /schedule has hard requirements that catch people by surprise.

01
What /schedule does
Sets a recurring task — for example, a daily digest delivered at 7 AM. The agent runs at the configured time and writes output to your folder.
02
The hard requirement
The machine must be awake and Claude Desktop must be open at run time. There is no background daemon — if the app is closed, the run does not happen.
03
Missed runs are skipped
A missed run is skipped, not queued. It catches up when the app reopens only if you configured a catch-up policy. Otherwise, you lose that run.
04
Verify manually first
Verify the first 2–3 runs manually before trusting automation. Confirm the output is in the right folder and looks correct before walking away.
05 — Session habits

Session hygiene

Small habits prevent the most common sources of poor output and lost context.

01
One task per session
Complex multi-topic sessions degrade — the model's attention spreads across too many threads. Start a new session for a new task.
02
Summary handoff
End a long session with: "Summarize what we did and what's still open." Paste the summary into the next session as your first message.
03
Where files land
Outputs go into the folder you granted access to. Check there first before assuming the file wasn't created.
04
Compaction is normal
When a session gets long, Cowork compacts older context. This is expected behavior, not a sign something went wrong. Carry forward what matters with a summary.
06 — Governance

Three rules to keep straight

The folder rule, the verification habit, and where work goes when it needs a central audit trail. Facts verified 21 July 2026 — treat the date as part of the fact.

01
The folder rule
Cowork reads and writes only in the folders you grant. There are no granular per-file permissions, so least privilege means picking a narrow folder rather than filtering inside a wide one. Point it at the narrowest folder that holds the job, and add a second one explicitly on the day it's genuinely needed.
02
"Local" is only half true
Cowork runs on the desktop against local folders, and code it needs to run runs in an isolated VM — but the model call goes to Anthropic's API, so whatever it reads from a granted folder leaves the machine to be processed. The files are local; the reasoning over them is not. Scope the folder as though everything inside it is being sent out, because functionally it is.
03
The verification habit
It drafts, you verify, you sign. Read the output back against the source before it goes anywhere: every claim traceable to a file, gaps flagged rather than filled. Whoever was accountable for the work before is accountable for it now.
04
The audit-gap routing rule
Claude Cowork activity is not captured in Anthropic's Audit Logs, Compliance API, or Data Exports on any plan tier, and conversation history lives locally on your machine. So work that needs centralized audit or zero retention runs on Anthropic's audited surfaces — the API or Claude Code Enterprise — not in the Cowork interface. Where a given piece of work falls is a call for the program team and IT: ask rather than assume.
07 — Get help

Who to ask when you're stuck

You're not on your own. Use these channels when a session goes sideways or a question comes up between the days.

In the session

Post in the Gen Re Cowork Teams channel or raise your hand in the room. Your cohort and facilitator are there in real time.

Between the days, and after

Office hours — your facilitator confirms the times in the room on Day 1 and again at the Day 3 close — and this portal: the resource library has every download, lab, and deck. Bring a real example: "here's what I tried" gets much better help than "it didn't work."
